# Prototype board: design

**Date:** 2026-10-15

**Status:** design agreed in conversation; written for the owner's review.

**Where it lives:** **everything for the prototype is in `prototype/`**: this spec, its plan, the scripts and every output (owner, 15 Oct). Production tools in `hw/` are imported and reused, never copied. Any change to one is a backwards-compatible parameter, proved by production regenerating byte for byte.

**Why:** nothing has yet shown the design working. The production board is blocked on the Bosch connector and the old ECU's housing. A prototype that sets both aside can be built now. It proves the circuits on the bench, and later carries the firmware and the Python engine simulator.

## Decisions taken in conversation (15 Oct)

| Question | Owner's answer |
|---|---|
| What goes on it | **The full production circuit**, all blocks unchanged |
| MCU | **STM32G474**, cheaper and easier to get than the S32K148. The production MCU choice is revisited after the prototype works |
| Separate dev board or one board | **One board**, with the MCU soldered on. A WeAct STM32G474CEU6 module is bought separately, for early firmware work only |
| Assembly | **Fab-assembled.** Which fab is decided later; the design must not depend on one |
| Routing | **Done here**: scripted placement, high-current copper as pours, Freerouting for the rest, then design-rule check until clean |
| Connector and housing | **Set aside.** Lab terminals replace the Bosch header |

## 1. What it must prove, and what success looks like

**It proves**, on the bench, with a bench supply and dummy loads:
- every block of the production circuit
- the STM32 circuit around them

**Success:**
1. `prototype/` holds a complete KiCad project, schematic and PCB, generated by scripts like production.
2. **Eight sheets are the production sheets, built by the production generators.** They differ from `hw/` only by the prototype additions in §3, and a check proves it.
3. **The netlist gate passes** with no open items. The prototype has its power-ground and trip-loop terminals, which closes production's two open items for this board.
4. **Every STM32 pin function comes from ST's own pin data,** checked by script, not by hand.
5. **The PCB is complete:**
   - 0 unrouted connections
   - 0 design-rule errors
   - 0 differences from the schematic
   - every power net in its class
6. **Fab files are written:** Gerbers, drill, parts list (BOM) and placement file. They are fab-neutral, so any of LionCircuits, PCB Power or JLCPCB can quote them.
7. **A bring-up guide is in the bible:** the order to power the board up, block by block.

## 2. Structure: reuse, don't copy

```
prototype/
  gen_prototype.py        builds the whole project into prototype/
  gen_sheet_mcu_stm32.py  new sheet: STM32G474 and its support
  gen_sheet_lab_io.py     new sheet: lab terminals instead of the Bosch header
  additions.py            prototype-only parts added to the built production sheets
  stm32_pins.py           pin assignment, checked against ST's pin data
  proto_rules.py          board outline, regions, terminals; imports hw/pcb_rules
  docs/spec.md, docs/plan.md   this spec and its build plan
  prototype.kicad_pro/.kicad_sch/... and the sheets
  prototype.kicad_pcb
  fab/                    Gerbers, drill, BOM, placement
```

- **Production sheets:**
  - `gen_prototype.py` imports each production generator's `build()` for power_input, rails, injector, metering_egr, sensors_analog, speed_inputs, discrete_io and can.
  - It applies `additions.py`, then writes the sheets into `prototype/`.
  - A production fix therefore reaches the prototype on the next run.
- **Root sheet:** `hw/gen_project.py` is parameterised by its sheet list and output folder, so production and prototype share one root generator.
- **Checks:** `hw/check_netlist.py`, `hw/gen_pcb.py` and `hw/check_pcb.py` are parameterised the same way: the root, the rules module, and the open-items list. They are not copied.
- **The supervisor and gate kill** (TPS3850 window watchdog, kill transistors at every protected gate; spec §4) move out of `gen_sheet_mcu.py` into a function both MCU sheets call. The prototype's safety cut-off is then the production one, not a copy.

## 3. The two new sheets, and the additions

### `mcu_stm32`

**The chip:**
- **STM32G474VET6:** LQFP-100, 170 MHz, 3 × FDCAN, 5 ADCs, −40…85 °C.
- The 64-pin RET6 was rejected: about 47 of its 52 I/O would be committed, and the timer and CAN functions sit on fixed pins.
- KiCad 7.0.11 symbol `MCU_ST_STM32G4:STM32G474VETx`; footprint `Package_QFP:LQFP-100_14x14mm_P0.5mm`.

**Its interface:**
- It exports **the same 42 signal names** as the production `mcu` sheet, so the other sheets connect unchanged.
- It adds:
  - `BOOST_MON`, the boost-rail monitor input
  - a `VBAT_PROT` monitor divider. `VBAT_PROT` is already exported

**Support parts, values from ST's datasheet and its hardware getting-started note:**
- **Decoupling:** 100 nF at each VDD pin and 4.7 µF bulk. VDDA and VREF+ through a ferrite, with 1 µF and 100 nF.
- **The production bulk capacitor** C313 with its 22 mΩ damping resistor, the `mcu_pdn.cir` finding, is kept.
- **8 MHz crystal (HSE)** with its load capacitors. CAN needs the accuracy.
- **NRST:** 100 nF. **BOOT0:** 10 kΩ to ground.
- **SWD debug header:** 2 × 5, 1.27 mm (the Cortex debug pinout).
- **USB-C, data only:** USB FS on PA11/PA12, a USBLC6-2 ESD diode, 5.1 kΩ on CC1 and CC2. The board is **not** powered from USB. That keeps the MCU rail to one source and rules out back-feeding.
- **Two LEDs:** 3V3 present, and a firmware status LED.

**Pin assignment:**
- It is decided in `stm32_pins.py` from ST's **STM32_open_pin_data** (the XML that ST's CubeMX tool uses). The extract is vendored with its checksum, as was done for the S32K148.
- A check proves each assigned function exists on that pin.

**What the chip must provide:**

| Function | Count |
|---|---|
| CAN (two FDCAN, classical CAN mode) | 2 |
| Crank and cam input capture | 2 |
| Injector outputs (3 low sides, 4 high sides) and metering PWM, as timer channels | 8 |
| EGR PWM and enable | 3 |
| Analog channels: 8 sensors, 2 battery feeds, 4 current senses, the sensor-supply monitor, the trip sense, `BOOST_MON`, the `VBAT_PROT` monitor | 18 |
| Discrete inputs | 5 |
| Relay outputs | 2 |
| Watchdog kick and fault | 2 |

**Every gate output must float at reset.** STM32 pins come out of reset in analog mode, so the production gate-kill reasoning holds. The check confirms no assigned gate pin is one of the debug pins that reset with a pull.

### `lab_io`

**Terminals:**
- It exports **the same 40 signal names** as the production `connector` sheet, each on a pluggable screw terminal: 5.08 mm, grouped by job and labelled with the production pin number.
- **Power and injector terminals are rated for their current:**
  - pin 21 logic feed
  - pin 04 injector feed
  - pin 06 EGR feed
  - **two power-ground terminals** wired to `GND`, the prototype's answer to production open item 5.1
  - the injector bank and low-side outputs
- **`TRIP_LOOP` gets a terminal,** answering open item 5.2 for the prototype.

**Isolation by supply:** pin 21, pin 04 and pin 06 are separate terminals. So the logic comes up with the injector and EGR stages simply unpowered. That is the isolation; no extra links are needed.

**A 2 × 10 bridge header** carries the crank pair, cam, the sensor inputs and ground. A future signal-bridge board plugs in here for the Python simulator, without changing this board.

### `additions.py`: added only to the prototype's copies of production sheets

- **Test points** (through-hole loops on the scope nets, pads elsewhere):
  - every rail: VBAT_PROT, VBAT_INJ, VBAT_EGR, 12V_GATE, 5V_MAIN, 3V3_MCU, 5V_SENSOR_A/B/C
  - **BOOST_100V**, marked HV
  - CAN1/2 H and L
  - CRANK_EDGE, CAM_EDGE
  - ISNS_INJ_A/B, ISNS_MU, ISNS_EGR
  - four ground loops
- **Boost-rail monitor:** a divider and filter from `BOOST_100V` on the injector sheet, exported as `BOOST_MON`. It is scaled so 116 V stays within the ADC's 3.3 V.

The production sheets in `hw/` are **not** changed by any of this.

## 4. PCB

| Item | Choice |
|---|---|
| Stack-up, classes, widths, clearances | **Production's** (`hw/pcb_rules.py`): 4 layers, 1.6 mm, 2 oz outer and 1 oz inner, Tg ≥ 170 °C, the ten classes. The prototype tests the production rules |
| New nets | USB D+/D− at 90 Ω differential; the rest Default |
| Outline | **220 × 160 mm**, 4 × M3 at the corners. The parts pack to about 15,300 mm²; the rest is room to route |
| Placement | By block, as production. **Terminals along two edges:** power and actuators on one, sensors, speed, switches and CAN on the opposite, each block beside its terminals |
| Critical loops | **Placed by explicit coordinates**, not shelf-packed: the boost switch loop, each injector turn-off loop, the buck loop, the feed filters, the MCU decoupling |
| High-current nets | **Copper pours, not tracks:** PWR_HI, HV100, RTN, PWR_LOOM and PWR, each over its block. L2 is one solid ground plane |
| Everything else | **Freerouting**, through KiCad's export and import (Specctra DSN/SES), honouring every class width and clearance. Java 27 is installed |
| Done when | 0 unrouted, 0 design-rule errors, 0 parity differences, `check_pcb` all pass |

**Known limits:** this is a **bench prototype**. Loop areas and pours are sized for function, not for the CISPR 25 Class 5 emissions target. Emissions are tested on the production layout.

## 5. Out of scope

- The firmware port to the STM32 (its own spec, next).
- The Python simulator and the signal bridge.
- Choosing a fab and ordering. The files are fab-neutral.
- The common-mode chokes and emissions work.
- The Bosch connector and the housing.

## 6. Risks

| Risk | Handling |
|---|---|
| Freerouting can't finish at production widths | Pours carry the high-current nets. If it still stalls: widen the outline, then let signal nets neck down only inside pads, never in PWR/HV classes |
| A production generator assumes `hw/` paths | Parameterise the output path; regenerating production must stay byte-identical (`test_schlib.py` already guards UUIDs) |
| `mcu_pdn.cir` was sized for the S32K148's current | Re-run the block with the STM32G474's supply-current figure from its datasheet before ordering |
| A part the fab doesn't stock | Fab-neutral BOM now; substitutions decided when quoting, each recorded |
